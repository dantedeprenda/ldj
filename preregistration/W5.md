# Pre-registration W5: does the frozen default rule hold on untouched comments?

Written and pushed 2026-09-30, **before** any model answer, prediction or score exists for the
fresh comments. The only facts known about them: 5,000 Measuring Hate Speech comments with ≥ 3
annotations, disjoint from T1's 5,000 (verified: zero overlap; T1's selection reproduced exactly),
27.4% labeled hate speech. Loader: `src/ldj/tasks/moderation_fresh.py` (task `t1_fresh`, seed
2026: a 3,000-comment pool and a 2,000-comment test set).

## What is tested

The rule frozen in `notes/default-rule.md` (commit `2f69bb2`), unchanged: question features plus
the zero-shot judge's probability under one logistic head (`questions_judge`; questions
`configs/questions/t1_v1.yaml` and the T1 judge instruction, both frozen since the T1
pre-registration), consensus labels, α = 0.10, δ = 0.05, the `ldj.certify` fixed-sequence
certificate. Split: f = 0.25 at B = 200 and 400; f = 0.50 at B = 800.

Comparators, on the **same label draws** (resamples seeded by (seed, group, B, rep)):
- **C1, direct judge:** the zero-shot judge, all B labels certifying (f = 0).
- **C2, fixed split:** question features alone, half the labels fitting (f = 0.50).

Configuration: `configs/w5_t1_fresh.yaml`; B ∈ {200, 400, 800}; 500 resamples; seed 0. The run
also produces other (method, f) cells; only the cells named here are confirmatory.

## Hypotheses (confirmatory)

Outcome: certified automation, the share of test comments automated, unconditional (a draw that
certifies nothing counts as 0). Paired difference over the 500 draws; 95% interval = 2.5th–97.5th
percentile of 10,000 bootstrap resamples of the draws.

| | Claim | Supported if |
|---|---|---|
| **H1 (primary)** | At B = 400 the rule automates more than the direct judge (C1) | interval lower end > 0 |
| H2 | At B = 400 the rule automates more than the fixed split (C2) | interval lower end > 0 |
| H3 | The rule's guarantee holds at every B | Clopper–Pearson 95% interval of the unconditional violation rate has lower end ≤ 0.05 at B = 200, 400 and 800 |

Secondary (reported, not tested): useful-certificate share, automation percentiles, violation
among useful certificates, the same comparisons at B = 200 and 800, and the whole-workflow ledger
at 10k items (consensus label = 3 actions, $0.25 per review).

## Predictions from development data (for the record, not criteria)

On T1 at B = 400 the rule automated 57.4% (useful in 94% of draws); the direct judge 9.5%; features
at f = 0.50 44.5%. A much smaller gap on fresh data would mean the development choices were fitted
to T1's test set.

## Procedure, failures, cost

1. Commit and push this file and the config (the timestamp is the record).
2. Fetch Gemma answers (questions and judge) for all 5,000 fresh comments; spend cap $5
   (`max_usd`). Failed calls are handled as in T1 (dropped from fitting, 0.5 at test) and counted.
3. Run the X4 allocation offline (local or Modal); compute H1–H3 with `scripts/w5_analyze.py`,
   written after this file but before the run's results are read.
4. Report every hypothesis as supported or not; deviations go in `notes/deviations.md`.

If H1 fails, the recommendation "use features + judge" is withdrawn for this source and the
simpler workflow that did best is reported instead.
